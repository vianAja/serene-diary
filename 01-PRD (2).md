# PRD — SereneDiary Revamp (Check-in & Notes)

## 1. Ringkasan
SereneDiary adalah web app checklist harian berbasis **Next.js 16 (App Router) + React 19**, dengan **PostgreSQL (Neon) via Drizzle ORM**, dan autentikasi **Google SSO (allowlist single-user)**. Dokumen ini mendefinisikan revamp besar (~80% perubahan visual) ditambah dua fitur baru:

1. **Daily Check-in** — hub task utama (tugas kuliah, materi kuliah, pekerjaan lain) dengan tanggal expire/deadline dan indikator urgensi visual.
2. **Notes** — catatan berformat Markdown yang bisa dipublikasikan agar dapat diakses publik tanpa login.

Ditambah redesign total ke arah **minimalist** (sedikit teks) dengan palet warna baru: `#F9F7F7`, `#DBE2EF`, `#3F72AF`, `#112D4E`.

## 2. Latar Belakang & Kondisi Saat Ini
- Stack: Next.js 16.2.6, React 19.2.4, Tailwind CSS v4, Drizzle ORM, Neon Postgres, NextAuth v4 (Google only + email allowlist).
- Fitur eksisting:
  - `/dashboard` — checklist harian dari template aktif
  - `/templates` — CRUD template checklist
  - `/reports/weekly`, `/reports/monthly` — rekap progres
  - `/calendar` — kalender & scheduled tasks
  - `/settings` — pengaturan
  - `/sign-in` — login Google SSO
- Semua halaman di grup `(app)` dilindungi middleware (`src/proxy.ts`); setiap route API memverifikasi sesi sendiri lewat `getAuthorizedUserId()`.
- Palet warna saat ini bertema soft sage/tan dan akan diganti total.

Detail teknis lengkap ada di `03-TECH-STACK.md`.

## 3. Tujuan Revamp
1. Menyederhanakan visual (minimalist, sedikit teks) dengan palet warna baru yang konsisten di semua halaman.
2. Menambahkan hub **Check-in**: task utama dengan deadline + indikator urgensi — **tanpa** membangun sistem notifikasi push/email di fase ini.
3. Menambahkan fitur **Notes**: catatan Markdown yang bisa di-toggle Public/Private, dan bisa diakses publik tanpa login saat Public.
4. Mempertahankan fondasi teknis yang sudah berjalan (auth, DB, deployment). Ini adalah **overhaul UI + penambahan fitur**, bukan rewrite total infrastruktur.

## 4. Target Pengguna
- **Primary — Najwan (Owner):** satu-satunya user terautentikasi (allowlist email), berperan sebagai mahasiswa sekaligus infrastructure engineer/trainer.
- **Secondary — Pengunjung Publik (anonim):** hanya bisa membaca Notes berstatus Public, read-only, tanpa akun.

## 5. Ruang Lingkup

### In-scope
- Redesign visual seluruh halaman existing + halaman baru, mengikuti palet baru & prinsip minimalist.
- Fitur baru: **Check-in** (task list akademik/profesional + deadline + status urgensi visual).
- Fitur baru: **Notes** (Markdown, toggle publish, halaman publik).
- Penyesuaian navigasi (sidebar desktop + bottom nav mobile).
- Penyesuaian skema database (tabel baru, tanpa menghapus data/tabel lama tanpa migration path yang jelas).

### Out-of-scope (fase ini)
- Sistem pengiriman notifikasi nyata (push notification browser, email, WhatsApp/Telegram bot). Yang dibangun **hanya data & indikator urgensi di UI**; arsitektur dirancang agar channel notifikasi bisa dicolokkan belakangan (lihat `03-TECH-STACK.md` §8).
- Multi-user/multi-tenant (tetap single allowlisted user + publik read-only untuk Notes).
- Kolom komentar / interaksi sosial di halaman Notes publik.
- Editor WYSIWYG kompleks untuk Notes (cukup textarea + live preview Markdown).

## 6. Fitur Utama (High-level)
Detail fungsional & acceptance criteria ada di `02-USER-REQUIREMENTS.md`.

### 6.1 Daily Check-in
Satu halaman yang menggabungkan checklist rutin (sistem template yang sudah ada) dengan daftar task berdeadline (tugas kuliah, materi kuliah, kerjaan lain). Setiap task punya kategori, tanggal expire, status selesai, dan badge urgensi (mendekati deadline / lewat deadline) — murni visual, tanpa notifikasi terkirim.

### 6.2 Notes (Markdown, Publik)
Najwan menulis catatan dalam Markdown, disimpan sebagai draft privat secara default, lalu bisa ditandai Public untuk dipublikasikan. Note Public dapat diakses siapa saja lewat URL publik tanpa login, dirender dari Markdown ke HTML dengan sanitasi.

### 6.3 Redesign Minimalist + Palet Baru
Semua halaman existing direstyle: teks dipangkas ke inti, hierarki tipografi disederhanakan, token warna diganti total ke 4 warna baru.

## 7. Non-Functional Requirements
- Kontras warna tetap harus terbaca (target WCAG AA), khususnya teks di atas warna gelap `#112D4E` dan primer `#3F72AF`.
- Halaman Notes publik harus SEO-friendly dasar (meta title/description per note).
- **Sanitasi HTML wajib** saat merender Markdown publik untuk mencegah XSS, karena kontennya dapat diakses siapa saja tanpa login.
- Tetap responsif mobile-first (bottom nav sudah ada, dipertahankan & diperluas untuk menu baru).
- Tidak menambah dependency berat; pilih library Markdown yang ringan.

## 8. Asumsi & Keputusan Desain
*(perlu dikonfirmasi Najwan sebelum eksekusi penuh — lihat juga catatan desain di `02-USER-REQUIREMENTS.md`)*

1. Menu "Daily" existing (`/dashboard`) di-refactor menjadi **"Check-in"** — bukan menu terpisah baru. Checklist rutin (template) tetap ada sebagai bagian dari halaman ini; task berdeadline adalah section tambahan di halaman yang sama.
2. Notes bersifat **single-author** (hanya Najwan yang bisa create/edit), dengan toggle Public/Private per note. Publik hanya bisa browse index + baca detail — tidak bisa menulis apa pun.
3. Nama aplikasi tetap **"SereneDiary"** (tidak diminta ganti nama).
4. "Notif" yang dimaksud pengguna = **indikator visual** (badge warna/label seperti "H-1" atau "Overdue") di dalam UI, bukan push/email/WA — sesuai permintaan eksplisit bahwa notifikasi bukan bagian dari core app.
5. Palet 4 warna yang diberikan tidak menyediakan warna semantik (kuning/merah) untuk status urgensi task. Opsi ditawarkan di `03-TECH-STACK.md` §7 — perlu keputusan Najwan.

## 9. Metrik Keberhasilan
Karena ini personal project, metrik bersifat kualitatif:
- Semua task kuliah/kerjaan tercatat dan status deadline-nya terlihat jelas dalam satu tampilan.
- Minimal satu note berhasil dipublikasikan dan bisa diakses tanpa login dari luar (mis. dibuka di browser incognito).
- Tidak ada regresi performa berarti setelah redesign (halaman tetap terasa cepat).

## 10. Risiko & Catatan
- Next.js 16 di repo ini punya breaking changes vs versi yang umum dikenal — lihat `AGENTS.md` di root repo, wajib dibaca sebelum menulis kode routing/middleware baru.
- Karena `/notes` perlu melayani dua audiens berbeda (manajemen privat vs listing publik), perlu pemisahan route yang hati-hati agar halaman manajemen tidak ikut ter-expose publik (lihat `03-TECH-STACK.md` §4–5).
